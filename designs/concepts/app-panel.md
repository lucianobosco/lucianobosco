# Concept: tunnels-manager v14.2 — the README *is* the app (and his private work is a 403 you can request access to)

> **Not built.** This is the full design from the research run, kept so it can be built
> later without redoing the work. Score: see `designs/README.md`.

## The pitch

You land on the profile and there is no profile — there's a running GTK4/libadwaita window titled **tunnels-manager  v14.2**, subtitle "lucianobosco · databases · data pipelines · video & stock platforms · Málaga, ES". Inside it, a live topology lane: `localhost 127.0.0.1` → dashed wire with blue packets crawling right and green ACKs crawling back → **identity-aware proxy** wrapped in a slowly rotating dashed handshake ring → **gke · cloud sql / europe-southwest1** with a breathing green LED. Below that, a GTK entry field where the connection string wipes itself into existence on load — `mysql://127.0.0.1:3307/stock-content ✓ established` — next to a blue **Copy ⧉** button and a latency sparkline that draws itself. The window ends in a real table header: TUNNEL · TYPE · LOCAL · TARGET · STATE · OPEN. And then the table rows arrive as separated libadwaita cards, each one a *link*: `tunnels-manager` sits green with its switch flipped ON → the repo. Under it, `video-platform`, `stock-content-db`, `data-pipelines` — dashed borders, amber spinners stuck mid-handshake, greyed switches with a padlock, **403 FORBIDDEN** in red and, under it, a small blue `request access ↗`. Click that and you get a prefilled GitHub issue; a workflow opens the tunnel, comments back with a real engineering write-up of that private system, and closes it. The version number is his years of experience. The ports are every default port +1, because the real one is already bound on your machine.

## Why it fits him and not a generic developer

Every other README with an app-shaped hero is cosplaying a product it doesn't have. He *has* the app: a GTK4 tool whose entire UI is a table of tunnels with a switch each and a connection string handed to you — so rendering his README as that exact table isn't a metaphor, it's a port. Three details make it unfakeable by anyone else: (1) `europe-southwest1` is GCP Madrid, which is where his data actually lives, in the country he lives in; (2) the local ports are `3307 / 5433 / 6380 / 7234 / 9091` — MySQL, Postgres, Redis, Temporal, Prometheus defaults *plus one*, the universal tell of someone who forwards production into a laptop that's already running all of them; (3) the version chip reads `v14.2`, his 14 years, so seniority is stated as a build number instead of a paragraph. Most importantly it solves his actual problem instead of hiding it: 4 public repos, 2 forks, 1 archived experiment. A normal profile makes that look like an empty career. Here, the private work is *rendered as infrastructure that exists and is deliberately firewalled* — six named systems with real stacks and real targets, gated behind 403s you can knock on. Scarcity becomes access control. That is a senior-infra joke, and only an infra person would land it.

## Techniques it relies on

- Hand-authored SVG committed to the profile repo, referenced with repo-relative <img> paths (bypasses camo entirely, 300s TTL, no cron, nothing to auto-disable)
- <picture> + <source media="(prefers-color-scheme: dark)"> with two committed SVGs per element — the only theme mechanism that follows GitHub's own toggle
- One <a>-wrapped <picture> per table row: clickability comes from markdown wrappers, never from <a> inside the SVG (verified inert)
- Interactivity via GitHub's prefilled new-issue URL (?title=access%7Crequest%7Cvideo-platform%7Cv1) + on: issues workflow — the chess-bot pattern repurposed as an access-request desk
- CSS @keyframes only (no SMIL), on straight-line wires so transform:translateX is sufficient and every animation is disableable
- prefers-reduced-motion handled by parking elements in their FINAL state in base CSS and animating away from it — a non-animating renderer shows the finished card, never a blank one
- Jinja template + rows.yml + palette token map -> 16 SVGs generated by one make target, so light/dark and column geometry cannot drift
- Generated SVGs XML-validated in CI (a stray & silently kills the whole image)

## Effort

Medium-high. ~1 evening for the hero panel (the fiddly part: hand-placing every x-coordinate, since no webfont loads and you cannot rely on glyph advance widths), ~2 hours for the row template + palette swap + render script, ~1 hour for the access workflow. I built and screenshot-verified the hero and two row cards in both themes already — prototypes at <local scratch dir> (head-{dark,light}.svg, row-tunnels-{dark,light}.svg, row-video-{dark,light}.svg) with the harness at ../harness.html. Total ~40 KB of SVG, no dependencies, no token, no cron.

## Risks

Four real ones. (1) FONT DRIFT: `ui-sans-serif`/`ui-monospace` resolve differently per OS and every column is a hard-coded x. Mitigation, already applied in the prototype: no dot-leaders, no centred text except inside pills, and each row's subtitle capped at ~52 chars — the first render I did overflowed the subtitle straight into the TYPE column, which is exactly how this design fails. Check on Windows/macOS/Linux before shipping. (2) PARAGRAPH GUTTERS: rows are one `<p>` each, so GitHub's 16px margin sits between cards. Cannot be removed (style is stripped; a `<table>` adds its own cell borders and padding). Design accepts it as a libadwaita "separated cards" list, which is why the hero ends in a column header rather than an open-ended table. (3) THE 403 ROWS MUST STAY HONEST — no invented metrics, no fake commit counts; every number is diegetic app chrome (`rtt 41 ms`) or true (v14.2, the port numbers, "3 open · 1 connecting · 3 forbidden" which literally describes the rows below). (4) THE ACCESS WORKFLOW IS OPTIONAL STAGE 2 and is the only moving part: anyone on the internet can open issues, so guard `if: startsWith(title,'access|')`, validate against a strict allowlist regex, pass the title via `env:` never `${{ }}` interpolation, `concurrency: {group: access}`, and be ready to set interaction limits. If it ever gets annoying, delete the workflow and repoint the three `request access ↗` rows at `mailto:` — the panel still reads correctly, which is the point of keeping the interactivity at the markdown layer.

## The hero SVG — structure and the two load-bearing tricks

`viewBox="0 0 880 272"`. Window `rect rx=13 fill=#1c1c20 stroke=#ffffff1f`; headerbar is a top-rounded `path` to y=44 (`M.5 44V13.5A13 13 0 0 1 13.5.5h853A13 13 0 0 1 879.5 13.5V44Z`) filled `#26262c` with a 1px `#ffffff14` separator. Title x=43 y=21 bold 13px, `v14.2` chip x=152 (pill `rx=7 fill=#62a0ea26`), one-line bio x=43 y=34 at 10px dim, `＋ New tunnel` ghost pill x=700, ⋯ dots at 822/829/836, close ✕ circle cx=860.

Topology lane, all wires **horizontal** so CSS translateX is enough:

Nodes: `rect x=24|366|706 y=76 w=150 h=58 rx=10 fill=#232329`, the IAP one stroked `#62a0ea59`; a padlock glyph; sublabels `127.0.0.1 · gtk4 · linux`, `tunnel: ESTABLISHED · 41 ms`, `europe-southwest1`. Connection field: `rect x=24 y=164 w=640 h=38 rx=9 fill=#131317 stroke=#ffffff24`, text 12.5 mono at x=38 y=188 with `<tspan>` coloring `3307` blue and `✓ established` green; blue `Copy ⧉` `rect x=676 w=86 rx=9 fill=#3584e4`; `rtt 41 ms` + a self-drawing `polyline` sparkline at x≥776.

Column header, aligned pixel-for-pixel with the row cards below (this is what fuses the separated cards into one table): 1px rule at y=226.5, then 9px letter-spaced dim labels at **x = 32 / 322 / 424 / 516 / 716 / 828**.

## Stage 2 — `.github/workflows/access.yml` (the 403s become real)

```yaml
name: access
on:
  issues:
    types: [opened]
permissions: { contents: write, issues: write }
concurrency: { group: access, cancel-in-progress: false }
jobs:
  grant:
    if: startsWith(github.event.issue.title, 'access|')
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Route request
        env:                                    # never ${{ }} inside a script body
          TITLE: ${{ github.event.issue.title }}
          ACTOR: ${{ github.event.issue.user.login }}
        run: python3 tools/access.py            # strict regex, else exit 78 / no-op
      - name: Reply and close
        env: { GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}, NUM: ${{ github.event.issue.number }} }
        run: |
          gh issue comment "$NUM" --body-file out/reply.md
          gh issue close   "$NUM" --reason completed
      - name: Commit audit trail
        run: |
          git config user.name  github-actions
          git config user.email github-actions@github.com
          git add data/sessions.jsonl panel/foot-*.svg
          git diff --cached --quiet || (git commit -m "access: session for ${ACTOR} [skip ci]" && git push)
        env: { ACTOR: ${{ github.event.issue.user.login }} }
```
`tools/access.py`: validate `^access\|request\|(video-platform|stock-content-db|data-pipelines)\|v1$` against `$TITLE`; anything else → exit without touching the issue (don't auto-close strangers' genuine issues). On a match, write `out/reply.md` from `docs/access/<system>.md` — a genuinely good 300-word write-up of that private system: what it ingests, the shape of the data, why Temporal and not cron, the query that used to take 40s. Append `{actor, system, ts}` to `data/sessions.jsonl`, re-render `foot-*.svg` so the status bar shows only the **last three** handles as connected clients (an audit log, not a visitor counter — no totals, ever). Prefilled issue body says "A bot replies in about 30 seconds", because it does.

Zero cron, zero PAT, zero third-party service: the only Actions run is the one a human triggers, and its own commits keep the repo active.
